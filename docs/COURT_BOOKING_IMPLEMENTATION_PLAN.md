# แผนพัฒนาระบบจองสนามและจัดการการจอง

วันที่ 14 กันยายน 2026 — จัดทำก่อนเริ่มแก้โค้ดในรอบนี้

## เป้าหมาย

ลูกค้าทั่วไปเลือกสนาม วัน เวลา ตรวจยอด และไปชำระเงินได้ง่ายบนมือถือ เจ้าของสนามเห็นงานที่ต้องทำและเปิดรายละเอียด/ตรวจสลิป/รับชำระได้ตรงรายการ โดยคงกฎราคา การกันเวลาจอง การจองซ้ำ คูปอง คิวรอ และการชำระเดิม

## สิ่งที่พบจากโค้ด

- หน้ารายการจองโหลดเฉพาะวัน แต่ไม่มีตัวกรองสาขา/สนาม/ช่องทาง ไม่มีรายละเอียดในหน้าเดียว และบางสถานะแสดงเป็นภาษาอังกฤษ
- ปุ่มตรวจสลิปพาไปหน้ารวม ส่วน POS ไม่ส่งรหัสจอง ปุ่มเช็คอินเดิมพาไปเช็คอินสมาชิกซึ่งไม่ใช่การเข้าใช้คอร์ท
- ตารางสนามใช้ทุกสถานะยกเว้น cancelled ทำให้ rejected/refunded อาจยังกีดกันเวลา และแสดงชื่อลูกค้าเฉพาะช่องเริ่มต้นของการจองหลายชั่วโมง
- วันที่ “วันนี้” บางหน้าคิดแบบ UTC แทนเวลาไทย
- การโหลดเวลาว่างและส่งการจองไม่มีตัวจัดการเครือข่ายล้มเหลวครบ จึงอาจค้างสถานะโหลด/บันทึก
- API เวลาว่างใช้ข้อมูลว่างแทนเมื่อ query ผิดพลาด ทำให้แสดงเวลาว่างที่เชื่อถือไม่ได้

## ประสบการณ์เจ้าของสนาม

1. เปิดหน้าการจอง เห็นวัน สาขา จำนวนรายการ รอตรวจสลิป รอรับชำระ และยืนยันแล้วทันที
2. ค้นหาชื่อ โทร รหัส หรือสนาม กรองสาขา/สนาม/ลูกค้าจองเองหรือเจ้าหน้าที่สร้าง/สถานะ คงตัวกรองใน URL เพื่อย้อนกลับหรือส่งลิงก์ภายในได้
3. แถวการจองจัดลำดับข้อมูลเป็นเวลา → สนาม → ลูกค้า → สถานะ → ยอด มีปุ่มหลักตามงานที่ทำได้จริงและตามสิทธิ์
4. เปิดรายละเอียดเป็น dialog ที่ใช้แป้นพิมพ์ได้ ดูข้อมูลลูกค้า รหัส หมายเหตุ สถานะ และช่องทางการจอง โทรหรือเปิดหน้าลูกค้าได้
5. ตรวจสลิปไปยัง payment ที่ตรง booking รับชำระส่ง booking/branch เข้า POS และการคืนเงินเข้าหน้าจัดการที่มีอยู่
6. ตารางสนามใช้เฉพาะสถานะที่กันเวลา แสดงชื่อและรายละเอียดตลอดช่วงหลายชั่วโมง กดช่วงว่างเพื่อสร้าง walk-in

## ประสบการณ์ลูกค้า

1. หน้าเลือกสนามแสดงชื่อสาขา ประเภท เวลาเปิด และราคาเริ่มต้นชัดเจน
2. หน้าจองแสดงขั้นตอนสั้น ๆ พร้อมวันเลือกด่วนและปฏิทิน เลือกเวลาต่อเนื่อง พร้อมราคาแต่ละช่วง
3. มีคำอธิบายว่าว่าง/ไม่ว่าง/เลือกแล้ว สรุปวัน เวลา จำนวนชั่วโมงและราคาใกล้ปุ่มดำเนินการ
4. กรอกข้อมูลติดต่อ คูปอง และหมายเหตุ กรอกสมาชิกให้อัตโนมัติ คงการจองซ้ำและคิวรอเดิม
5. อ่านนโยบายและยอมรับก่อนดำเนินการ คูปองต้องตรวจจากเซิร์ฟเวอร์ ปุ่มไม่แสดงยอดก่อนตรวจคูปองว่าเป็นยอดสุทธิแน่นอน
6. โหลดตารางมี skeleton, empty และ retry; เปลี่ยนวันยกเลิกคำขอเก่า ปิดการแก้ฟอร์มระหว่างส่ง เมื่อเครือข่ายล้มเหลวกลับมาใช้งานต่อได้

## แนวทางออกแบบ

- ใช้สีและฟอนต์เดิมของ SportHub: พื้นผิวเรียบ การ์ดมุมโค้ง สี brand เป็นจุดเน้น ใช้ success/warning/danger ร่วมกับข้อความสถานะ
- Dark/light ใช้ theme tokens ไม่ใช้พื้นสว่างตายตัว ตัวอักษรสำคัญอ่านได้ชัดและมี focus ring
- มือถือจัดหนึ่งคอลัมน์ ปุ่มกดสะดวก; จอใหญ่ใช้พื้นที่สำหรับข้อมูลหนาแน่นและสรุปการจอง
- ใช้ไอคอนจากระบบเดิม ไม่มีการโหลดภาพ/ไลบรารีใหม่เพื่อการตกแต่ง

## ข้อมูล ความเร็ว และสิทธิ์

- อ่านข้อมูลเจ้าหน้าที่ผ่าน session และตรวจ tenant/สาขาที่ได้รับมอบหมาย รวมสถานะ active ของเจ้าหน้าที่
- โหลดชุดข้อมูลอิสระพร้อมกัน เลือกเฉพาะฟิลด์ที่ใช้ จำกัดรายการต่อหน้า พร้อมข้อมูลจำนวนและ pagination
- ตัวกรองที่จำกัดข้อมูลใช้ server query; การเลือกดูรายละเอียดใช้ข้อมูลที่โหลดแล้ว ไม่ต้องเปลี่ยนหน้า
- API สาธารณะไม่ส่งข้อมูลผู้จอง ถ้าอ่านข้อมูลจอง/บล็อกไม่สำเร็จให้ตอบ error แทนตารางว่าง
- ใช้กฎ buildSlots และสถานะกลาง ไม่เปลี่ยนกฎราคา/กันจองซ้อนในฐานข้อมูล
- ไม่สร้างการเช็คอินคอร์ทหรือการเลื่อนเวลาจองแบบหลอก ๆ: การเพิ่มทะเบียนเข้าใช้/เลื่อนพร้อมปรับราคาเป็นงานธุรกรรมแยก ต้องออกแบบ schema ก่อน

## ลำดับพัฒนาและตรวจรับ

1. หน้าจัดการ: query/สิทธิ์/ตัวกรอง/รายละเอียด/ลิงก์ตรงรายการ/สถานะโหลดและผิดพลาด
2. ตารางสนาม: สถานะกันเวลาและการจองหลายชั่วโมงถูกต้อง
3. หน้าจองลูกค้า: โครงหน้าใหม่ สรุปยอด ปุ่มวันด่วน การโหลด/ส่งฟอร์มที่รับมือเครือข่ายผิดพลาด
4. ตรวจ TypeScript, lint ส่วนที่แก้, unit tests สำหรับวันจริง/ช่วงเวลา/สถานะ และ production build
5. ตรวจจริงก่อนเปิดใช้: guest จอง → อัปโหลดสลิป → พนักงานเปิดรายการตรง → อนุมัติ → สถานะลูกค้าเปลี่ยน; ทดสอบต่าง tenant/สาขา, จองพร้อมกัน, ราคา peak, คูปอง, คืนเงิน, มือถือและ dark/light

## ข้อจำกัดการยืนยันผล

การเข้าถึง browser และ Supabase จริงถูกปฏิเสธในงานก่อนหน้า ยังไม่มีสิทธิ์ใหม่สำหรับช่องทางนั้น จึงตรวจโค้ดและ build ได้ แต่ไม่อ้างว่า visual QA หรือธุรกรรม production ผ่านแล้ว งาน POS เดิมและ migration ที่เตรียมไว้จะถูกเก็บไว้

## ผลพัฒนาในรอบนี้

- เปลี่ยนหน้าจัดการเป็น Booking Desk: ตัวกรองใน URL, ค้นหาชื่อ/โทร/รหัส, สาขา/สนาม/ช่องทาง/ทุกสถานะ และ pagination 40 รายการ พร้อมจำนวนรวมตามตัวกรอง
- มีปุ่มลัดงานรอตรวจ/รอชำระ/ยืนยันแล้ว เปิดรายละเอียดใน dialog ได้จากแถว และลิงก์ไปสลิปที่ตรงรายการหรือ POS พร้อมรหัสจอง/สาขา ปุ่มลัดไม่แสดงจำนวนที่คำนวณจากแค่หน้าปัจจุบัน
- เจ้าหน้าที่ inactive เข้าหน้าจัดการ/ตารางไม่ได้ และ query จำกัดสาขาที่ดูแล ไม่มีการแสดงปุ่มเช็คอินสมาชิกว่าเป็นการเช็คอินคอร์ท
- ตารางสนามแสดงการจองตลอดทุกชั่วโมง รวมช่วงที่เริ่มเล่นแล้ว แสดงช่วงที่ refunded/rejected เป็นเวลาที่ไม่ถูกกันโดยรายการนั้น และตรวจว่าข้อมูลอ่านมาครบก่อนแสดงเวลาว่าง
- หน้าเลือกสนามจัดการ์ดตามสาขา หน้าจองมีวันเลือกด่วน ขั้นตอน 1–3 และสรุปด้านข้างบนจอใหญ่ ใช้หนึ่งคอลัมน์บนมือถือ เพิ่มคอนทราสต์และปุ่มที่ใช้สีตามธีม
- คงสมาชิก/คูปอง/จองซ้ำ/คิวรอ ป้องกันคำขอตารางเก่าทับวันที่ใหม่ มี retry และจัดการเครือข่ายผิดพลาด ทั้งหน้าจองและส่งสลิป/ยกเลิก
- หน้าติดตามมีลำดับขั้นและอัปเดตสถานะด้วยตนเองได้ การตรวจสถานะอัตโนมัติหยุดส่งคำขอเมื่อหน้าต่างไม่อยู่ใน foreground
- API เวลาว่างและการสร้างจองไม่ใช้ข้อมูลว่างแทน query ที่ล้มเหลว ตรวจวันที่จริงและสาขาเปิดให้บริการก่อนรับจอง
- ไม่เพิ่ม migration สำหรับงานหน้าจองรอบนี้ การส่งต่อไป POS ยังต้องใช้ migrations POS ที่เตรียมไว้ก่อนหน้า

ผลตรวจ: unit tests 93 รายการใน 15 ไฟล์ผ่าน และ lint เฉพาะหน้าจอง/จัดการ/ตาราง/API เวลาว่าง/ส่วน booking ที่แก้ผ่าน ไม่ได้อ้างว่า lint ทั้งโปรเจกต์หรือ UAT production ผ่าน

Production build ของชุดส่งมอบผ่าน รวม TypeScript และการสร้างหน้า static 100 หน้า (exit code 0)

งานที่ต้องตรวจจากระบบจริง: guest จองและส่งสลิป, อนุมัติด้วย role/สาขาที่ถูกต้อง, การจองพร้อมกัน, การยกเลิกและคืนเงินรวม POS, ภาพหน้าจอมือถือ/แท็บเล็ต/เดสก์ท็อปและทั้งสองธีม ยังไม่เพิ่มการเลื่อนเวลาหรือทะเบียนเข้าใช้คอร์ทในรอบนี้

## รอบต่อยอดฐานข้อมูลและงานหน้าสนาม (14 กันยายน 2026)

ข้อความผลรอบก่อนข้างต้นเป็นประวัติการส่งมอบ ไม่ใช่สถานะล่าสุด รอบนี้เพิ่ม migration `20260914000000_booking_operations.sql` และ UI เช็กอิน/จบการใช้งาน/ไม่มาตามนัด ประวัติการจัดการ และเลื่อนวันเวลาแบบคงสนาม ระยะเวลาและราคาเดิม รวมทั้ง transaction ยกเลิกและตรวจสลิปที่ใช้ booking row lock ร่วมกัน

การเลื่อนข้ามสนาม/ราคาเปลี่ยนและการย้อน attendance ยังไม่อยู่ในโฟลว์นี้ รายละเอียดการนำขึ้นฐานข้อมูล ข้อจำกัด และ UAT อยู่ใน [COURT_BOOKING_DATABASE_DEPLOYMENT.md](COURT_BOOKING_DATABASE_DEPLOYMENT.md) ไม่มีการ push production ในรอบนี้

Unit tests ล่าสุดผ่าน 106 รายการใน 17 ไฟล์ ครอบคลุมเพิ่มเรื่องสิทธิ์ สาขา validation และการตอบเมื่อ RPC ล้มเหลว เป็น mocked tests ไม่ใช่ผลรัน SQL จริง

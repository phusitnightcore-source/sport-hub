# SCOPE.md — ระบบจัดการแข่งขันแบดมินตัน (Badminton Tournament Manager)

> Stack: **Next.js (App Router, TypeScript) + Supabase (Auth, Postgres, Realtime) + Vercel**
> เอกสารนี้คือขอบเขตเดียวที่ยึดถือ ห้ามทำเกินขอบเขตนอกเฟสที่กำลังทำอยู่

---

## 1. เป้าหมายของระบบ

เว็บแอปเดียวจบสำหรับจัดการแข่งขันแบดมินตัน ครอบคลุม:

1. **กดคะแนนสด** ตามกติกาแบดมินตัน (BWF) พร้อม UI สนามแสดงตำแหน่งผู้เล่นและฝั่งเสิร์ฟ
2. **จัดสายแข่งขัน** หลายรูปแบบ หลายระดับมือ ผู้ชนะขยับสายอัตโนมัติ
3. **หน้าสาธารณะ** ดูสาย ผลสด ตารางแข่ง โดยไม่ต้องล็อกอิน
4. **ระบบสมาชิก** แยกสิทธิ์ Admin / กรรมการ / นักแข่ง ชัดเจน

---

## 2. บทบาทผู้ใช้ (Roles)

| Role | สิทธิ์ |
|---|---|
| **admin** | ทำได้ทุกอย่าง: จัดการทัวร์นาเมนต์, event, นักแข่ง, จับสาย, มอบหมายกรรมการ, กดคะแนน, แก้ผลย้อนหลัง, จัดคอร์ท |
| **umpire (กรรมการ)** | เห็นเฉพาะแมตช์ที่ถูกมอบหมาย, กดคะแนนสด (บวกแต้ม/Undo/จบเกม/จบแมตช์/walkover/retired) เฉพาะแมตช์ของตัวเอง, แก้ข้อมูลอื่นไม่ได้ |
| **player (นักแข่ง)** | สมัครสมาชิก/ล็อกอิน, ดูโปรไฟล์ตัวเอง (ข้อมูลส่วนตัว, ระดับมือ, สถิติแพ้-ชนะ, ประวัติแมตช์, ตารางแข่งที่จะถึง), แก้ได้เฉพาะ ชื่อเล่น/เบอร์โทร/รูป — **ระดับมือ admin กำหนดเท่านั้น** |
| **public (ไม่ล็อกอิน)** | ดูหน้าสาธารณะทั้งหมด: สาย, คะแนนสด, ตารางแข่ง, ผลย้อนหลัง |

หมายเหตุ:
- Admin เป็นคนเปลี่ยน role ให้ user (default ตอนสมัคร = player)
- นักแข่งที่ยังไม่สมัครสมาชิก admin สร้าง record ให้ก่อนได้ (player ไม่ผูก user) แล้วค่อยผูกบัญชีทีหลัง

## 3. โครงสร้างการแข่งขัน

```
Tournament (งานแข่ง 1 งาน)
 └── Event (ประเภท × ระดับมือ เช่น "ชายคู่ มือ S", "หญิงเดี่ยว มือ N") — เพิ่มได้ไม่จำกัด
      └── สายการแข่ง (bracket) ของ event นั้น
           └── Match → Game (เกม 1-3) → Score Event (log ทุกแต้ม)
```

- **ประเภท event**: ชายเดี่ยว, หญิงเดี่ยว, ชายคู่, หญิงคู่, คู่ผสม
- **ระดับมือ**: admin สร้าง/แก้เองได้ (เช่น มือใหม่ N, S, P-, P, C, B) เก็บเป็นตาราง `skill_levels`
- **รูปแบบสาย 3 แบบ**:
  1. `single_elim` — แพ้คัดออก รองรับ bye อัตโนมัติเมื่อจำนวนทีมไม่เป็น 2^n
  2. `round_robin` — พบกันหมด มีตารางคะแนน (ชนะ 1 แต้ม, ตัดเสมอด้วย: จำนวนชนะ → เกมได้-เสีย → แต้มได้-เสีย → head-to-head)
  3. `group_knockout` — แบ่งกลุ่มพบกันหมด → ที่ 1-2 ของกลุ่มเข้ารอบแพ้คัดออก
- **จับสาย**: สุ่ม หรือ admin จัดเอง + วางมือ seed ได้
- **ขยับสายอัตโนมัติ**: match มี `next_match_id` + `next_match_slot` เมื่อจบแมตช์ ผู้ชนะถูกใส่ช่องถัดไปทันที (ทำใน DB function ฝั่ง server เท่านั้น)
- **คอร์ทและคิว**: match ระบุ `court_no` + `scheduled_at` ได้

## 4. กติกานับแต้ม (Scoring Engine) — ต้องถูกต้อง 100%

> Logic นี้เขียนเป็น pure function ใน `src/lib/scoring/` มี unit test ครบทุกเคส ห้ามกระจาย logic ไปไว้ใน component

1. Rally point: ฝั่งชนะแรลลี่ได้ 1 แต้มและได้สิทธิ์เสิร์ฟ
2. เกมละ 21 แต้ม, 20-20 ต้องชนะห่าง 2, ตัน 30 (29-29 ใครถึง 30 ก่อนชนะ), แมตช์ชนะ 2 ใน 3 เกม
3. **ช่องเสิร์ฟ**: คะแนน "ฝั่งเสิร์ฟ" เป็นคู่ → เสิร์ฟจากคอร์ทขวา, คี่ → คอร์ทซ้าย
4. **เดี่ยว**: ผู้เสิร์ฟยืนซ้าย/ขวาตามคะแนนตัวเอง ผู้รับยืนคอร์ททแยง
5. **คู่**:
   - ฝั่งเสิร์ฟได้แต้ม → **คนเดิมเสิร์ฟต่อ** แต่สลับช่องซ้าย-ขวากับคู่ตัวเอง
   - ฝั่งรับได้แต้ม → สิทธิ์เสิร์ฟย้ายฝั่ง **ผู้เล่นไม่สลับตำแหน่ง** คนที่ยืนตรงช่องที่ถูกต้อง (ตามแต้มคู่/คี่ของฝั่งตัวเอง) เป็นผู้เสิร์ฟ
   - state ต้องเก็บตำแหน่งผู้เล่นทั้ง 4 คนว่าใครอยู่ช่องไหน
6. Interval แจ้งเตือนเมื่อฝั่งใดถึง 11 แต้ม, เปลี่ยนฝั่งเมื่อจบเกม และในเกม 3 เมื่อฝั่งใดถึง 11
7. **Undo ได้ไม่จำกัด** ย้อนทีละแต้ม (ใช้ score_events เป็น source of truth — ลบ event ล่าสุดแล้ว replay)
8. จบแมตช์แบบพิเศษ: walkover (ไม่มาแข่ง), retired (บาดเจ็บกลางแมตช์)

### UI สนาม (Scoring Console)
- แสดงสนามแบดมุมมองบนลงล่าง แบ่ง 4 ช่อง เห็นชื่อผู้เล่นในตำแหน่งจริง
- ไฮไลต์คนถือลูกเสิร์ฟ + ลูกขนไก่ + ทิศเสิร์ฟ
- ปุ่มบวกแต้มใหญ่ 2 ปุ่ม (ฝั่งละปุ่ม แตะบนมือถือ/แท็บเล็ตง่าย), ปุ่ม Undo, ปุ่มจบแมตช์
- แสดงคะแนนเกมปัจจุบัน + เกมที่จบแล้ว + ป้าย interval/game point/match point

## 5. หน้าจอทั้งหมด (Route Map)

### สาธารณะ (ไม่ต้องล็อกอิน)
| Route | หน้าที่ |
|---|---|
| `/` | รายการทัวร์นาเมนต์ (กำลังแข่ง/จะถึง/จบแล้ว) |
| `/t/[tournamentId]` | ภาพรวมทัวร์นาเมนต์ + รายการ event + แมตช์สดตอนนี้ |
| `/t/[tournamentId]/e/[eventId]` | สายการแข่ง (bracket/ตารางกลุ่ม) แมตช์สดมีจุดแดง live + คะแนน realtime |
| `/t/[tournamentId]/schedule` | ตารางแข่งเรียงตามคอร์ท/เวลา + ผลที่จบแล้ว |
| `/live/[matchId]` | ดูแมตช์สดเต็มรูปแบบ (คะแนน + สนาม, read-only) |
| `/display/[matchId]` | โหมดจอใหญ่/โปรเจคเตอร์ ตัวหนังสือใหญ่ auto refresh |

### Auth
| Route | หน้าที่ |
|---|---|
| `/login`, `/register` | เข้าสู่ระบบ / สมัครสมาชิก (email+password ผ่าน Supabase Auth) |

### นักแข่ง (role: player)
| Route | หน้าที่ |
|---|---|
| `/me` | โปรไฟล์ + สถิติ + ประวัติแมตช์ + แมตช์ที่จะถึง |
| `/me/edit` | แก้ข้อมูลพื้นฐาน (ห้ามแก้ระดับมือ) |

### กรรมการ (role: umpire)
| Route | หน้าที่ |
|---|---|
| `/umpire` | รายการแมตช์ที่ถูกมอบหมาย (วันนี้/ทั้งหมด) |
| `/umpire/match/[matchId]` | Scoring Console (UI สนาม) — เข้าได้เฉพาะแมตช์ตัวเอง |

### Admin (role: admin)
| Route | หน้าที่ |
|---|---|
| `/admin` | Dashboard ภาพรวม |
| `/admin/tournaments` (+new/edit) | จัดการทัวร์นาเมนต์ |
| `/admin/tournaments/[id]/events` | จัดการ event ในทัวร์นาเมนต์ |
| `/admin/events/[eventId]/entries` | เพิ่ม/ถอนผู้เข้าแข่งขัน (เดี่ยว=1 คน, คู่=จับ 2 คนเป็นทีม) |
| `/admin/events/[eventId]/draw` | จับสาย: สุ่ม/ลากวาง/วาง seed → generate bracket |
| `/admin/events/[eventId]/schedule` | จัดคอร์ท เวลา และมอบหมายกรรมการรายแมตช์ |
| `/admin/players` (+new/edit) | จัดการนักแข่ง + กำหนดระดับมือ + ผูกบัญชี user |
| `/admin/skill-levels` | จัดการระดับมือ |
| `/admin/users` | จัดการ role ผู้ใช้ (เลื่อนเป็น umpire/admin) |
| `/admin/match/[matchId]` | Scoring Console เดียวกับกรรมการ + แก้ผลย้อนหลัง |

## 6. ขอบเขตแต่ละเฟส (ทำตามลำดับ ห้ามข้าม)

### เฟส 1 — MVP (core ต้องเสร็จก่อนทุกอย่าง)
- [ ] Setup: Next.js + Supabase Auth (@supabase/ssr) + schema.sql + RLS + middleware
- [ ] ระบบ role: admin / umpire / player + guard ทุก route
- [ ] Admin: CRUD ทัวร์นาเมนต์, skill levels, นักแข่ง, event
- [ ] Entries + จับสายแบบ **single elimination** (สุ่ม + bye อัตโนมัติ)
- [ ] Scoring engine (pure function + unit tests ครบ: เดี่ยว, คู่, ดิวส์, ตัน 30, undo)
- [ ] Scoring Console + UI สนาม (admin และ umpire ใช้ร่วมกัน)
- [ ] มอบหมายกรรมการรายแมตช์ + หน้า `/umpire`
- [ ] ขยับผู้ชนะเข้าสายอัตโนมัติ
- [ ] หน้าสาธารณะ: `/`, `/t/[id]`, bracket + คะแนนสด realtime, `/live/[matchId]`

### เฟส 2 — จัดการแข่งขันเต็มรูปแบบ
- [ ] Round robin + ตารางคะแนน + กติกาตัดเสมอ
- [ ] Group + knockout (แบ่งกลุ่ม → น็อกเอาต์อัตโนมัติ)
- [ ] วาง seed + ลากวางจัดสายเอง
- [ ] จัดคอร์ท/คิว + หน้า `/t/[id]/schedule`
- [ ] โปรไฟล์นักแข่ง `/me` + สถิติแพ้ชนะ + ประวัติแมตช์
- [ ] Walkover / retired

### เฟส 3 — เสริม
- [ ] โหมดจอใหญ่ `/display/[matchId]`
- [ ] Head-to-head ระหว่างนักแข่ง
- [ ] นักแข่งสมัครลงแข่งเอง → admin อนุมัติ
- [ ] Export ผล/สายเป็นรูป/PDF

### นอกขอบเขต (ไม่ทำ)
- ระบบจ่ายเงินค่าสมัคร, แอปมือถือ native, ระบบ ranking ข้ามทัวร์นาเมนต์แบบ ELO, live video streaming, แจ้งเตือน push/LINE

## 7. เกณฑ์ว่า "เสร็จ" (Definition of Done ต่อฟีเจอร์)
1. ทำงานถูกต้องตามกติกา/ขอบเขตข้อ 3-4
2. RLS ปิดช่องโหว่ (ทดสอบด้วย user แต่ละ role แล้ว)
3. Scoring engine ผ่าน unit test ทั้งหมด
4. หน้าสาธารณะดูบนมือถือได้ (responsive)
5. Deploy บน Vercel แล้วใช้งานได้จริง
